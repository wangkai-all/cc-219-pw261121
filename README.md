# 订单交付能力 · 供需对照（ATP）本地工具

一个零依赖的本地 Web 工具：导入现货、已确认采购、生产计划、已有占用与新需求，按 **物料 × 日期** 计算还能承诺多少（ATP）。全部使用虚构供应链数据，**不连接真实 ERP，也不会自动下采购单**。

## 启动

```bash
node server.js        # 默认 http://localhost:3210
npm test              # 运行分配引擎测试（11 个用例）
```

## 功能对照

| 需求 | 实现 |
|---|---|
| 供需对照页 | 「供需对照」面板：每个物料一张日期网格（确认供给 / 情景供给 / 需求 / 累计供需差 / 可承诺余量 ATP） |
| 未确认供给单列 | 未确认采购（RFQ）标记为「情景」，默认不参与承诺；顶栏开关可纳入，且承诺结果始终带「含情景供给」标记 |
| 库存不重复承诺 | 分配引擎按供给池扣减，同一批库存只承诺给一张订单（有测试保障） |
| 物料替代 | 替代规则含比例（1 组兼容料 = 0.95 组原料）与生效期（按订单交期判断），消耗按替代料最小单位向上取整 |
| 取消 / 延迟重分配 | 供给清单中可取消、恢复、延迟；自动重算并在「影响分析」中列出受影响订单及调整前后承诺交期，同时写入「调整记录」 |
| 新增分析订单 | 订单面板表单，实时重算并显示对其他订单的影响 |
| 切换分配优先级 | 按交期 / 按订单优先级 / 按下单先后（已有占用订单始终最先分配） |
| 展开供需对应关系 | 点击物料行展开：每张订单 ← 供给批次、数量、到货日、是否替代/情景 |
| 情景比较 | 「确定可交付」与「纳入情景」两套承诺日期并排对比 |
| 最小单位尾差 | 每种物料有最小数量单位，分配向下取整，不足一个单位的尾差在订单行与物料展开区单独列示 |

## 内置虚构场景

- **共享物料争抢**：MAT-A 主控芯片被 4 张订单争抢，含插单 SO-2006（优先级 1）
- **部分到货**：PO-8802 拆为首尾两批（11-28 / 12-10）分别参与承诺
- **物料替代**：MAT-B 缺口 60 组 → 消耗 80 组兼容料 MAT-C（比例 0.95、限 11–12 月生效）
- **尾差**：SO-2005 需求 355 片，按最小单位 30 取整，尾差 25 单独列示
- **情景**：未确认报价 RFQ-12 若落实，SO-2002 承诺可从 12-10 提前到 12-01

## 结构

```
server.js          零依赖 HTTP 服务（静态文件 + JSON API + 状态持久化到 data/store.json）
src/engine.js      分配引擎（纯函数）：供给池、优先级排序、替代、取整、ATP 网格、影响 diff
src/seed.js        虚构数据集
public/            单页前端（原生 HTML/CSS/JS）
test/engine.test.js  引擎规则测试
```
